## 已完成的桌面修复

- 两个 Electron 入口的顶层 `await app.whenReady()` 阻塞 ESM 加载，导致 ready 永远不触发。改为不阻塞入口加载的异步初始化，并报告启动错误。
- 从 Electron Node 模式启动 MCP 时，Broker 错把 Electron 模块对象当作可执行路径，且 GUI 继承 `ELECTRON_RUN_AS_NODE=1`。改用当前 Electron 可执行路径，并从 GUI 环境移除该变量。
- macOS 首次显示全屏覆盖窗口时将其限制到工作区，实测从 `(0,0)` 移到 `(215,34)` DIP。启用全屏边界后，与 `(0,0,1710,1107)` 显示器边界完全一致。
- 显示器布局变化重建窗口后，`did-finish-load` 回调中仍可能 `isLoading()`，导致已有标注一直隐藏。改在 `did-stop-loading` 重画，并加入真实窗口重建回归。
- 原生定位失败的代码在 Bridge 被丢弃，MCP 只能返回 `broker_error`。保留结构化定位错误，区分同意、权限、前台和目标丢失。
- 打包应用从 MCP 唤起时仍会进入 package.json 主入口，重复建立 Broker 导致启动失败；加入已配置 Bridge 的附着入口。包内 MCP 原生 helper 改从 extraResources 解析，避免依赖不存在的 ASAR 内 Swift 源码。
- 原生跟随从每次查询完成后等待 2500 ms 调整到 500 ms；保留串行查询、失效撤标和本地计算，不增加模型调用。

## 真实 Codex 与用户交接

Codex MCP 已通过 `codex mcp add` 注册绝对 Node/源码路径，启用 compact 输出和 `HANDOFFGLASS_HOST_ID=codex`；保留其他配置并备份原配置。

当前对话实际加载 9 个 HandoffGlass 工具。`screen_displays` 返回 `connected:true`、`headless:false`，真实 Retina 显示器为 1710×1107 DIP、scaleFactor 2。实际调用 `handoff_request`，用户在面板点击完成，`handoff_status` 和 `handoff_events` 均返回完成；从 started 到 completed 为 5.372 秒。

该测试的 `completionSource` 为 `user_report`、`verified:false`；它证明请求、显示、人工决定和事件返回链路，不证明下游应用任务已经完成。另一个真实 desktop demo 的用户响应耗时为 25.387 秒。
